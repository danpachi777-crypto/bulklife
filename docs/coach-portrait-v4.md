# BULK LIFE 0.5.0 — 選手とコーチの計画

既存の育成・生活・大会の計算を使い、目標と生活条件から具体的な計画を選べるようにした。人物は同じMakeHuman系の連続人体と骨格を改良し、タイトル・ホーム・身体確認で共用する。写実品質の完成や、全姿勢の衝突解消を意味しない。実際の画像と確認範囲は [確認報告](qa/coach-portrait-v4/report.md)。

## 計画を選ぶ

- 新規開始は「大きくする／引き締める／整える／相談する」と練習時間・食費から開始。6種類の抽選と各1/6、身体・生活条件、既存の勝敗条件は維持。
- 今日の採用済み計画と相談中の未採用案を区別。30分、軽め、休養、節約、重点部位から、実際の種目・セット・時刻・食品量・睡眠を組む。外部AI APIは不要。
- コーチ担当の練習・食事カードは初心者向けの相談を開く。食事はプランを先に表示し、数値入力を要求しない。詳細設定も残す。
- 採用する項目を練習・食事・休養ごとに指定。詳細で保存した項目は手動になり、自動計画が上書きしない。採用せず閉じても変更しない。
- 日送り後、コーチ担当の当日の練習だけを身体・疲労・生活条件から更新する。食事や手動項目は自動変更しない。週間まとめ実行は、画面に表示した週間計画をそのまま実行し、従来の重要判断で停止する。

食事の食品成分は既存データを共用する。同じ予算でも食品量・準備時間・栄養充足が変わる。節約案はゲーム内の仕入れ費用係数0.83・準備係数1.35、手軽な案はサービス費用1.38・準備0.35。これらはゲーム設定で、現実の自炊・外食の栄養評価ではない。予定だけでなく `nutritionPlan` が同じ費用・時間をシミュレーションへ渡す。少額予算で確保できない栄養を架空の最低カロリーで補わない。

エネルギー案は既存の消費式（体重×29、練習時間×210、実施有酸素×4）とゲーム内の目標差から作る。目標・成分量・負担はゲーム内選手への提案であり、利用者本人への医療・栄養指導ではない。

## 経過と保存

任意フィールド `coachingGuide` に方針、各項目の担当、最大28日分の実績、見直し時期を保存。既存セーブにこのフィールドがなければ、計画を変更しない。採用時に既存のキャリア拡張を使う。IndexedDB・JSON書き出し・読み込みの構造を共用し、追加フィールドを検証する。過去の実績を推測して埋めない。

14日連続の実績が集まってから、前後7日の平均体重・筋質量推移と目標を比較して食事量の見直しを提案する。1日差では変更しない。採用は明示操作、再確認は14日後、逆方向への再調整は28日以上空ける。資金不足や食事の不足がある場合は配分の相談を優先する。週の区切りには直近7日の実施セット・睡眠・身体推移を実績から表示する。

日次結果は実績、捉え方、次の操作を示す。未実施や疲労などを記録から説明し、筋肉が毎日目に見えて増える演出は行わない。

## 人物とジム

- 唇を閉じた待機顔、上下まぶた、顎・首・鎖骨、膝への移行と背面の面を調整。眉を重複した線から毛方向のある面へ変更。
- CC0短髪のカードを頭皮へ合わせ、側面の膨らみと襟足を整理。ゲームではアルファ判定と色を明示し、透過の重なりを抑制。
- CC0の独立した縫製メッシュから、丸い襟のトレーニングトップと別体のショーツを作成。ゆとり、厚みのある端、座位の小さなしわを追加。身体確認時の短パンと用途を分ける。
- 衣服の変形転写は胴体・脚に制限。近くの手を拾う不具合と、座位補正に別の体型が混じる不具合を修正。衣服の内側に完全に隠れる皮膚だけを着衣時に非表示にし、裸の身体確認では元の全表面を戻す。
- 19クリップを維持し、長めの待機、控えめな呼吸・頭の動き、指の曲がりの差、膝へ置く手を調整。ブラウザでは実際のまぶたの変形による瞬きと小さな視線移動を追加。動きを減らす設定を尊重。
- ジムはBlenderで作成した同じGLBを共用。ベンチのクッション・フレーム・ゴム足、ダンベルの六角重り・金属グリップ、ロッカーの扉・換気孔、奥行きのある窓、控えめな床の継ぎ目を制作。主光・補助光・背面光を中立寄りへ調整。
- 全身・上半身・顔、正面・側面・背面、操作ロック、視点リセット、比較表示を維持。補助操作は折りたたみ、人物の表示を優先する。

## 制作データと復元

元v2・v3のblend/GLBは変更せず、[元データのハッシュ](qa/coach-portrait-v4/original-hashes.json)を保存。復元ブランチは `backup/pre-coach-portrait-20261121`。最初の作業複製は `assets/blender/bulk-life-athlete-v4-work.blend`、使用する復旧済み制作ファイルは **`assets/blender/bulk-life-athlete-v4-final.blend`**。

ライブBlender 5.3へ実接続して編集したが、ジム書き出しで応答停止した。別プロセスでも保存されたシーンの依存グラフ評価がアクセス違反で終了したため、作業複製から必要なデータを新しいシーンへAppendして復旧した。元ファイルは上書きしていない。元の応答停止ウィンドウは強制終了していない。

再制作は `recover_portrait_v4.py`（読み取り専用の作業複製から復旧）、`final_garments_v4.py`、`correct_cloth_key_v4.py`、`final_groom_motion_v4.py`、`close_lips_v4.py` の順。以後の再書き出しは最終ファイルを開いて `export_portrait_v4.py`。比較画像は `render_portrait_v4.py`、読み込み用静止画は `render_loading_v4.py`。後者は着衣・座位の制作プレビューも保存する。書き出し時だけ皮膚の非表示モディファイアを無効にし、ゲームへ元の連続表面と変形を渡す。BlenderのPythonから実行する。最後に `npm.cmd run assets:portrait` でハッシュ付き参照を更新する。

```powershell
npm.cmd run check
npm.cmd test
npx.cmd tsx scripts/verify-portrait-v4.ts
npm.cmd run build
```

出典とCC0原本は `assets/sources/makehuman-system-v3/` と `assets/sources/makehuman-clothing-v4/` に保持。後者の元素材はTシャツ・長ズボンで、完成したジムウェアをそのまま取得したものではない。有料購入は行っていない。
