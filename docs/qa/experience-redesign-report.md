## 検証で見つけた問題と修正

| 問題 | 修正 |
|---|---|
| 食品計画が有効なのに、別の集約値を設定/表示できた | 使用中の食事を明記。ホームと日次結果は同じnutritionPlanを利用。簡単設定を変える操作ではそちらに切替 |
| 日次の過去の予定/技能/疲労が残らない | detailを当時の値で保存し、旧記録の未記録を区別 |
| 補助練習が時間不足でも全量加点 | 実施できた時間に制限し、実績を保存 |
| 大会の完了当日に通常練習もできた | 当日の大会時間と休養を日次処理/UIへ反映 |
| 新旧モデルのクリック部位/ヒート表示の向きが違った | glTFのY-up座標を部位定義のZ-upへ変換。実メッシュのraycastで回帰検証 |
| 過去の3Dに現在の身体数値が並び紛らわしい | 数値も選択時点へ切替。未記録の全身回復と、現在の技能を明示 |
| 調理時間の入力に浮動小数点の端数が長く表示された | 表示を整え、フォーカス移動だけでは実設定を変更しない |
| 抽選中の候補をimportで保護できない | 復元と、現在候補を別の保存枠へ残す処理を追加 |
| 候補の遅延自動保存が、開始/再抽選/復元後の保存と競合し得る | ライブラリー置換前に未発火のタイマーを取消し、進行中の書込を待ってから確定 |
| ローカル出場者の引退文が大会未出場となる | ローカルと公式参照大会の出場数を分けて記録 |
| 大会結果が一覧のはるか下に追加された | 結果へ自動移動し、今日の作戦へ戻るボタンを追加 |

`npm.cmd run build` も成功。初期JS 381.39KB（gzip 120.20KB）、遅延3D 1,084.80KB（gzip 303.66KB）、CSS 35.89KB（gzip 8.18KB）。3Dは初期コードから分離し、必要時に読み込む。3Dチャンクが500KBを超えるVite警告は残る。
