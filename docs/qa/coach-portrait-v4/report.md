# BULK LIFE 0.5.0 確認報告

既存の育成・生活・大会を残し、初心者向けコーチと人物・衣服・ジムの改修を組み込んだ。見た目は改善途中であり、要求された写実品質をすべて満たしたとは評価していない。制作方法・出典・復旧手順は [制作記録](../../coach-portrait-v4.md)。

## 改修内容

- 新規開始は目標・練習時間・食費から計画を作る。今日のおすすめを採用し、専門数値を入力せず進行できる。
- 30分、疲労、休養、予算、重点部位の相談から実際の種目・セット・食品量・睡眠を提案。提案と採用済み計画を分け、練習・食事・休養を個別に採用する。詳細保存した項目は手動として保護する。
- 食事プランは費用・準備時間・栄養が異なり、実行にも同じ値を渡す。14日分の傾向から承認式の食事見直しを提案し、7日分の実績を振り返る。外部AI APIは使わない。
- 閉じた口元、まぶた、眉、首・鎖骨・身体の面、短髪、独立したトップとショーツ、指・待機・座位、瞬きと視線を調整。衣服への手の誤ウェイト、座位補正に別体型が混ざる問題、靴グループの表示不整合を修正した。
- Blenderで作ったベンチ・ダンベル・窓・ロッカー・床を実際のゲームへ読み込み、中立寄りの照明を共用。人物を大きく保ち、計画要約と実行ボタンへ到達しやすくした。

## 初心者の一日を実際に操作

ユーザーの既存選手を進めないため、独立オリジン `http://127.0.0.2:5178/` にQA用選手「蓮」を新規作成した。

1. タイトル→6種類の抽選→目標・45分・850円→おすすめで開始。
2. 相談で30分を選び、未採用の提案を確認して採用。実行結果は7/7セット・30分・食事2144kcal/P104g/849円・睡眠8時間。実行ボタンを二重クリックしても1日だけ進んだ。
3. 疲労・予算500円・休養の相談を採用。休養日は0セット・0分。実際の食事1434kcal/P79g/500円、手動で指定した睡眠9時間が維持された。
4. 再読み込み→つづきからで2日経過、日付、所持金、計画、手動設定を復元。
5. 食事カードから数値入力なしでプラン一覧を開き、「手軽」を食品だけに採用。499円・準備15分へ変化し、練習30分と手動睡眠9時間は変わらなかった。

## 自動確認・データ保護

- テスト94件成功。6初期パターン、30分による実際のセット減、軽めの刺激・疲労、食費・準備・栄養、部分採用・手動保護、週間実行と元計算/RNGの一致、14日見直し、結果文、旧セーブ・保存再開・破損データを含む。
- 型検査を含む本番ビルド成功。PWAキャッシュ23ファイル・約17.2MB、Manifest standalone、現在のv4人物とジムを含むことを確認。[ビルド情報](build-report.json)。
- 実GLTFLoaderで5体型×9動作×3時点＝135ケースと立ち上がり37時点を検査。衣服の腕への誤ウェイト、瞬き・座位補正、非有限値等を検査した。[ランタイム検査](runtime-report.json)。CPU検査のテクスチャは寸法スタブで、画質・FPS・全接触の証明ではない。
- 元v2/v3制作4ファイルとCC0原素材22ファイルのSHA不変。[保護確認](preservation-report.json)。追加ガイドは任意フィールドで、未採用の既存セーブへ自動挿入しない。
- 元Blenderファイルを直接上書きせず複製した。ライブBlenderの書き出しが応答停止したため、新しいシーンへAppendして別プロセスで復旧した。編集用は `assets/blender/bulk-life-athlete-v4-final.blend`。元の停止ウィンドウは強制終了していない。

## 未達と制約

- 写実寄りの人物としての完成度は未達。髪カードの輪郭、顔・耳・手足の細かな造形、脚と上半身の肌の統一、発達体型の関節周辺の輪郭に改善余地がある。
- 衣服は独立メッシュ・形状補正・内側皮膚の表示制御で対応している。布物理、全体型×全動作の衝突解消、姿勢ごとの完全な接触は未達。
- スマホ確認はWindows Edgeの画面幅変更とタッチエミュレーション。iPhone Safari・Android Chrome実機、物理的なピンチ、端末FPS/発熱、新版PWAの実機オフライン・更新は未検証。
- コンソールにはThree.js/R3F由来のClockと影方式の非推奨警告が残る。観察した操作で進行を止めるエラーは発生しなかった。3D JSは未圧縮約1MBで、初回通信・低性能端末の負荷は残る。
- セーブはブラウザ内保存で端末間の自動共有はない。既存のJSON書き出し・読み込みを使用する。PWAは取得済みキャッシュが前提で、LANのHTTPアクセスからのインストール/オフライン利用を保証しない。

## スマホで開く

PCを起動して開発サーバーを維持し、スマホを同じWi-Fiへ接続して **http://192.168.2.197:5178/** を開く。PCでは http://localhost:5178/ 。確認時は既存サーバーが `0.0.0.0:5178` で待受し、LAN URLのHTTP応答を確認した。IPが変わった場合は `npm.cmd run lan:url` で再確認する。新しい課金・素材購入・公開先へのデプロイは行っていない。
