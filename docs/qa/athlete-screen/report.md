# BULK LIFE 主画面の改修と検証

## 参考作品を操作して採用したもの

公開中の各作品で開始、人物紹介、選択と結果、詳細をChromeで操作した。選択時のDOMと計算済みスタイルを390pxと1280pxで記録した。コード調査の対象はブラウザーに配信されたHTML、CSS、JavaScript。各JSONには取得したリソースのURL、確認したセレクター、操作履歴を収録した。

| 作品 | 公開画面とコードで観察したこと | BULK LIFEへの反映 |
|---|---|---|
| 80億分の1 | 誕生から最初の決断まで進み、選択後に家族の詳細を開閉。上部の `#scene.scene` はCanvasを内包するdiv。外側の `.panel.p-scene` はスマホ幅358px、PC幅540px。 | 身体の変化を毎回見られる位置に実データ駆動の選手を置いた。筋肉を確認できる上半身のカメラと、同じ選手の全身への切替を用意。 |
| この土地に生まれて | 家庭と仕事に関する選択を確定し、人物の詳細を開閉。配信HTML内の `.pagebody` は縦スクロール。選択領域の幅は324pxから586pxへ拡大した。 | 育成の出来事、決断、直近の結果を一続きにした。結果の身体・資金差分は確定記録から表示。 |
| パラレルライフ | 誕生から幼少期を進め、選択後の画面変化と資金内訳への操作を確認。`.choice-label` は16px、`.choice-hint` は14px。配信CSSにセーフエリアと動きを減らす設定がある。 | カード全体で選択し、行動名の下で利益と代償を比較する。確定ボタンと下部ナビを分け、結果を読む速度はプレイヤーが決める。 |

公開コードと計測値の対応は [80億分の1](reference-0.json)、[この土地に生まれて](reference-1.json)、[パラレルライフ](reference-2.json) に収録。元リポジトリや非公開の保存処理は調査対象外。パラレルライフは2回に分け、選択後の表示変化と、資金内訳の開閉をそれぞれ確認した。

## 操作で確認した範囲

- 390×844、360×640、375×667、430×932、360×540、1280×850をChromeで計測。3Dの高さは順に186、154、154、205、145、374px。全寸法で横あふれはなく、約50pxの確定ボタンは下部ナビの上に収まった。短い画面では縦にスクロールして選ぶ。[測定結果](layout.json)
- キーボードでカードを選び、上半身と全身を切り替えて同じCanvasを使用すること、拡大から戻って選択が残ることを確認。360×540の文字サイズ200%でも決断を確定できた。指導者を選んだプレイでは桐谷からの測定会の案内と、筋質量+0.49kg・資金+51,238円の実績を同じ画面で読めた。
- 大会日から逆算した残り12週、8週、4週を入力して、各時点で重点部位55分、通し稽古40分、軽負荷30分の別々の方針が実際に選べることを [大会カレンダーの回帰テスト](../../../tests/season-circuit.test.ts) で確認した。
- seed 231の友人ルートでは、涼と近所のジムで開始し、同じ大会を目指した後、勤務の変更を受けて大会を分けた。第4回に友人の本番を実際に手伝うと、第6回にそのお礼が届いた。初回に食費を調整しても友人の予定は残った。第3回の連打は両ルートで1回の決断として記録。大会の発表前に再読み込みして復帰し、順位発表を進めた。
- 同じseed・選択で日本挑戦から続行した経路と、世界挑戦から開始した経路を記録。各決断の見出し・候補・実行した行動・大会・日付、20回と40回の比較用ハッシュは [日本挑戦から続行](domestic.json) と [最初から世界挑戦](direct.json) を参照。比較から実行時刻と実行ごとの識別子を除いた。
- 実機のiOS Safari、Android端末のGPU、読み上げソフトの音声、全経歴・全出生地の組み合わせは今回の計測範囲外。過去の別ルートの記録は [分岐検証](../turning-points/report.md) にある。

両経路で40回分の選択履歴が一致した。20回時点のハッシュは `76b8f4a5…02bee25e`、40回は `382df074…9cd18659` で一致。筋質量は初日比で国内編終了時に+9.3kg、世界編終了時に+12.9kg。後半で日本大会3位、アジア大会3位、国際大会3位に到達し、最後に出場した大会はリーフジム測定会1位だった。続行前の国内結果は40回終了後も同一だった。製品ビルド成功、自動テスト131件成功。
