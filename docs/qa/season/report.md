# 大会カレンダーと主画面の検証

## 選択と記録

開始・再開後の主画面に、現在の日付と年齢、目標大会、選手の姿、今回の出来事、選択肢が並ぶ。カードを押すとチェックが付き、下部の進行ボタンで確定する。日常の結果は次の出来事と同じ主画面に残る。大会と20・40回の区切りでは発表を待つ。選手の経歴や数値の内訳は必要なときに開ける。以前の必須だったカード詳細と、通常期間ごとの「次の作戦へ」の操作を省いた。[変更前](../life-story/decision-1.png)・[現在の主画面](home.png)・[選択中](decision.png)

食費・目的・勤務などを編集しても、同じ出来事の選択と相手を保持する。実プレイでは、最初に涼と近所のジムを選び、その作戦の食費だけを1,350円に変更した。確定履歴に人物ID `origin-B34` と食費1,350円が一緒に残り、涼が同じ大会を目指さないかと誘ってきた。単発の遠征食は予定当日だけ日次計算に渡す。指導や設備を変更して元の人物予定が成立しなくなる場合は、その作戦での確定時に理由を表示する。

## 年次カレンダー

すべて架空のBULK男子サーキット。通常の新規選手は1年に5回、約4年で国内20回、そのまま約8年で40回を迎える。日数は3月1日・5月25日・7月31日・10月1日・翌年1月4日の境界と実際の日付から求める。年に4回のジム測定会と、各シリーズ年1回の公式戦を分けた。今季の正式出場は最大3回。資格・目標設定・有料の申込・辞退・出場・順位発表を区別する。

県オープンは9月15日開催、締切9月1日、参加費と交通費は計4,700円。3位以内なら翌年8月16日の地方オープンに申し込める。地方3位以内で翌年の日本GP、日本GP3位以内でアジア招待戦、その後も国際オープン・世界予選・世界ファイナルと進む。申込は開催150日前から14日前まで。費用は登録時に一度支払い、辞退時の返金はない。開催回IDとゲーム内日付からその日の身体で審査する。期間末まで残り日数があれば、その後の育成も進む。

## 通しプレイと保存

Windows版Chrome 157、390×844、動きの低減あり。Playwrightが通常のカードと進行ボタンを操作。各ログに全候補、選択、期末日、食費、人物、大会と成績、国内・世界の状態ハッシュ、自動操作秒数がある。

- [国内20回から40回へ](domestic.json) と [最初から40回](direct.json) は、ともにseed 231で同じ選択。国内では県オープンで7位を経験し、翌年2位。地方オープン4位で次の日本GP資格を逃した。再度県大会から挑み、後半に地方、日本GP、アジア招待戦、国際オープンへ進んだ。優勝して得られるのは次のシリーズの資格で、その先の開催回は別途申し込む。両入口で20回・40回の選手状態と国内記録を照合した。
- [自主練習と出場見送り](training.json) はseed 823。大会への申込なしで国内20回と世界編40回の結末まで到達。コースを選んだだけで国際資格や成績は付かなかった。
- 3回目は進行ボタンを二重に実行し、記録件数は1件だけ増えた。大会の順位発表前に再読み込みして再開した後も、同じ開催回の結果を受け取れた。
- [旧セーブ移行](migration.json) では旧制度の国内優勝セーブをインポートし、元のセーブを残して別枠へ移行した。国内結果と全20件の履歴が一致。旧実績から期限付きのアジア招待戦の資格を引き継ぎ、世界ファイナルの資格は付かなかった。進行中の旧ジョブは元の計算を終えてから移行する。
- 360・375・390・430pxの横幅を検査。文字サイズ200%で進行可能。キーボードで選択し、大会カレンダーに移動して戻っても選択とスクロール位置を保持した。[画面とメモリの計測](screen.json)

Chromeの自動操作は国内から続行が414.4秒、最初から世界編が406.9秒、出場見送りが369.6秒。公式戦の最上位到達は2034年国際オープン1位で、最後の出場は同年12月のジム測定会1位だった。「次の開催までの仕上げ方」は出場経路で5回、見送り経路では7回出現した。違う年度に再登場する題材は残る。各ログで見出しと候補を追跡できる。自動操作の待ち時間にはブラウザ描画、育成計算、IndexedDB保存も含まれる。人が読むのに要する時間と読後の疲労感、実機iOS・Androidの操作感は未計測。

## 人物の変更

Blender 5.3で開いた実ファイルは標準・長身・幅広の3体型。作業中のユーザーのシーンは開いたまま、各ファイルを別プロセスで処理した。対象は `BL_V2_AthleteBody`（メッシュ `BL_V2_AnatomicalSurface`）、リグ `BL_V2_Rig`、タンク、トレーニングショーツ、大会ショーツに存在する対応キー。メートル単位。標準の身体のワールド変換は単位行列。骨の位置では人物本人の左上腕の根元はおよそ (0.191, −0.011, 1.397)m。+Xが本人の左、+Zが上、正面撮影は−Y側。服については頂点をリグローカルへ変換して修正範囲を求めた。

肩の成長キーで横・奥行き・高さの変位をそれぞれ0.84・0.91・0.86倍にし、上腕への付着部に向かってさらに弱めた。胸外側は肩幅に応じて変位を最大26%抑えた。上腕・大腿は長軸上の位置に応じて筋腹と末端の変位を変え、前腕は元の成長差分を1.06倍にした。変更するのは該当キーの差分で、骨格・身長・接地・体脂肪キー・クリップは保持した。[変形処理](../../../assets/blender/refine_contours.py)

対戦相手の下顎に片側最大5mmの幅を持たせる表情とは独立したキーを追加。髪の粗さ0.66・異方性0.30、白目の粗さ0.30・コート0.16、ニットと織布のSheen Weight（布の縁に見える反射）0.18をBlender側に設定した。3つの作業用blendからゲーム用GLBを出力し、ハッシュ付きの読込URLを更新した。[顔と素材](../../../assets/blender/finish_calendar_materials.py)

同じ標準体型の旧版と新版のGLBを読み直し、同じポーズ・カメラ・照明で比較した。[変更前](before/)・[変更後](after/)・[再現用スクリプト](../../../assets/blender/compare_contours.py)。正面・横・背面、腕を上げた姿勢、座位で比較可能。腕と胸の差は控えめ。肩・脇の細かな筋肉の境目、座位での指一本ずつの接地、髪と肌の写実性はなお改善の余地がある。既存リグの19クリップ、3体型のロード、形状キー、スキニングは自動テストで確認した。

## 参考作品で操作したこと

- 80億分の1では出生から人生を開始し、「次の決断まで」で進め、幼少期に物を回して見つめる選択を実行した。人物の現在と選択場面を往復せず確認できた。[80億分の1](https://1in8b.life/ja/)
- この土地に生まれてでは家族の抽選から出生の記録に進み、育児と仕事の選択で「仕事はいつも通り続け、帰ってから手伝う」を選んだ。人物紹介を閉じると同じ時系列へ戻れた。[この土地に生まれて](https://nakata-ataru.com/konotochi/play/)
- パラレルライフでは抽選した人物で年を進め、大学進学・学費・学生生活を選んだ。短い選択の下に費用や生活への影響が添えられていた。[パラレルライフ](https://parallel-life-phi.vercel.app/)

BULK LIFE独自の実装は、次の開催回の残り週数を常設し、選ぶ動作と期間を確定する動作を分け、その結果を同じ選手の練習・出場履歴へ結びつけた点にある。

## 再検証

`npm test` で130件、`npm run build` で本番ビルドを確認。ブラウザスクリプトは `BULK_PREVIEW` で接続先を指定できる（既定4191番）。PlaywrightとChromeを用意して `node scripts/play-season.cjs domestic`、`direct`、`training` の3経路を実行する。`scripts/check-season-migration.cjs` は `scripts/audit-turning-points.ts` が生成する旧国内優勝アーカイブを使用する。`node scripts/verify-season.cjs` が2入口の全選択・20回と40回の状態・重複出場の有無を照合する。
