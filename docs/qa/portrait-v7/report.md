## 原因と実際に修正したもの

| 対象 | 調査で確認した原因 | 修正 |
|---|---|---|
| ゲームの髪の黒い欠け | 配信GLBの髪はalphaMode BLEND。Three.jsで透明表示を切り抜きへ変更した後も、読み込み時のdepthWrite=falseが残り、後ろのカードが前へ描かれていた | 深度の書込みを有効にし、切り抜き・両面・多重サンプリングをまとめて設定。複数素材へ分かれた髪の子メッシュにも適用 |
| 眉と顔 | 顔の表面を動かした後、眉の根元が古い面に残り、皮膚へ埋まる箇所があった。近傍点へ寄せるだけでは位置も偏る | 顔の正面からのレイで眉の根元を置き直し、毛を複数の区間で細くする。まぶたの厚み、眉骨、頬骨、口元、顎を実頂点で修正。瞳を0.9mm下げ、白目の明るさと反射を調整 |
| 短髪の形 | 側頭部・襟足まで同じ厚みのカードが残り、頭頂と側面の長さの差が弱い | 既存CC0素材の生え際を保持し、頭頂を残して側面/襟足を頭皮へ近づけた。上部へ方向のある細い立体の毛束を追加。直線の固い頭皮キャップ案は比較で却下 |
| 後頭部と体脂肪による髪/眉のずれ | カードの間から頭皮が線状に見える箇所と、平たい濃色のカード中心が残っていた。固定した毛の根元は脂肪量による頭部変化へ追従しない | 後頭部のカード中心を、頭の面に沿う下地と方向のある毛束へ置換。襟足の矩形の段差も連続した曲線へ整えた。髪と眉に実際のbodyFat変形を転写し、育成値へ接続 |
| 高筋量の胸・肩・脇 | 薄い胸郭の上に旧い局所変形が重なり、腕上げ時の前側の脇と肩の体積が不足。胸中央に狭い凹みが出る | 胸骨から上腕へ細まる胸の形、三角筋の前/横/後ろの厚みを修正。腕上げ用の肩と前側の脇、肘曲げ時の筋腹に補正を追加。狭い段差を局所的に整え、連続皮膚と関節位置を維持 |
| 襟・袖ぐり・裾 | 不均一な縁、肩の先端、元シャツの裾が残る。縁の頂点番号順をそのまま面の向きにすると途中で反転し、帯も交互に裏返っていた | 縁を閉じた曲線として順番に処理し、布の面から法線を求め直した。4mm幅・約0.9mm厚の縫い代を実メッシュで制作。全体型/座位/腕上げの変形と骨のウェイトを共有 |
| 腰の皮膚 | 裾を直しても、古い非表示範囲が残ると本来見える腰まで消える | 新モデルでは見える腰を保持する非表示範囲へ変更。腰の三角形が消えない回帰テストを追加 |
| 衣装の表示切替 | 複数素材の衣装はGLBでは親グループと子のスキンメッシュへ分かれる | 親グループごとウェアを切り替え、身体確認で縫い代だけが残らないようにした |
| 腕上げ時の画面切れ | 身体詳細の全身カメラが待機姿勢と同じ距離と注視点だった | ダブルバイセップスとプレスの全身表示では距離と注視点を変更。幅360pxで指先まで収まることを実画面で確認 |

顔立ちや人種的特徴を欠点として変更していない。同じ人物を保ち、目を大きくしたり、口を開けた演技で生きているように見せたりしていない。皮膚の模様を増やすことや照明の変更を、造形修正の代わりにはしていない。

## 制作とゲームへの反映

ライブBlender連携は300秒でタイムアウトした。接続できたとは報告しない。インストール済み公式Blender 5.3のバックグラウンド処理で、v6を複製した `assets/blender/bulk-life-athlete-v7-work.blend` を実際に編集・保存・書き出し・再読み込み・描画した。

配信先は `public/assets/athlete-v7.glb`、メタデータは `public/assets/portrait-v7.json`。`npm.cmd run assets:portrait` が内容ハッシュを `src/view/portraitAsset.ts` のURLへ反映する。実際の読み込み処理と開発用の識別表示を共通にし、タイトル・通常画面・身体確認・大会・比較で同じ更新を使う。基準v6との切替は開発用人物確認画面だけにあり、本番の自動フォールバックではない。

旧モデル名 `athlete-v2` の互換参照を維持しているため、既存のキャリア、乱数、筋量・脂肪・疲労・資金・大会結果はそのまま。新しい挑戦には作成時の表示版を記録し、過去の表示版と現在の描画を区別する。セーブ形式の変更やデータ移行は不要。

v2〜v6の制作ファイルと配信モデル11ファイルを、`cdb928b` の内容ハッシュと比較して保護を確認した。新しい有料購入や生成サービスの課金はない。既存のCC0素材の元ファイル22件も来歴とハッシュを確認した。

## 比較画像の条件

[画像ギャラリー](gallery.html) に修正前後、体型、ゲーム内の表示をまとめる。

- Blenderの前後は、同じ体型値、ポーズとフレーム、カメラ位置、画角、照明、背景、画質で撮影。
- 顔の正面/斜め/横、髪の背面、裸の正面/側面/背面、高筋量の大会正面/背面、単色の肩・胸・脇を比較。
- ウェア立位/腕上げ/高脂肪座位、襟と裾の接写、まばたきの閉眼を確認。
- 細身、標準、中間、筋肉質、筋肉と脂肪が多い体型も描画。
- ブラウザでは、元のv6、描画だけを直したv6、造形・素材も直したv7を分ける。髪の黒い欠けが消える差を、モデルの造形変更として説明しない。
- 固定カメラ・同じ体型・動作停止の比較を用意し、実際のゲーム画面の証拠と、Blender描画を混同しない。

元のCC0素材やGTA VIの公式公開画像は参考の観察資料であり、固有のモデル・画像をゲームへコピーしていない。今回も既存の [出典と確認範囲](../consistency-v5/references.md) を引き継ぐ。

## 検証

全自動テスト115件成功。追加2件は実際の配信GLBをThree.jsで読み込み、半透明髪の深度設定、髪のbodyFat、分割された衣装/縫い代のスキンと体型/ポーズ用ターゲット、裾の下の腰の皮膚を検証。型検査と本番ビルドも成功。

最終資産の9体型×9クリップ×3時点の243ケースと、立ち上がり37時点を、実際の読み込み・スキニング・変形で検証した。有限値、範囲、変形の接続の検証であり、全フレームの無衝突や見た目の合格を証明するものではない。

実ブラウザの操作・描画計測の記録は `browser-verification.json`、資産とビルドの検証結果は `runtime-report.json` / `build-report.json` / `preserved-originals.json` を参照。スマホ実機は利用できず、Windows ChromeでPCと幅360/393/430 CSS pxのスマホ相当画面を確認した。物理iPhone/Safari・Android/Chromeで検証したとは報告しない。

PC（Core i5-1235U / Iris Xe、Chrome、DPR1、軽量画質）では、ウェア付き高筋量ポーズの631×410領域が約59fps、101〜106描画呼出。スマホ相当では既存の30fps制限に沿う約30fps。動作停止時の1fpsは必要時だけ描画する結果であり、性能の上限ではない。後頭部の最終曲線調整前の計測と、最終モデルの識別情報はJSONで区別して残す。

今回のブラウザ確認は保存済み選手の再開、タイトルの座位、身体、顔、正面/側面/背面、ウェア切替、腕上げの再生、回転とスクロールの切替、初日と最終身体の2体表示。今回新たに20/40決断を手動で完走したとは扱わず、前回の完走記録を維持する。

描画性能、全身と接写での印象、体型やポーズの自然さは、自動テスト成功と分けて評価する。今回は指摘された表示破綻・根元のずれ・服の縁・体型補正を具体的に直した更新であり、映画用の実写人物やリアルタイム布シミュレーションを導入したものではない。

残る制作上の制約：接写では髪のカードと立体毛束の境界が一部読める。極端な高筋量での脇と胸の面は手作業の連続彫刻ほど細かな構造を持たない。服の縁はスキニングと補正形状であり、布の衝突計算は行わない。これらを隠すために暗くした画像は提出していない。襟足、肩、脇、衣装について、通常距離と近接の両方をギャラリーで確認できるようにした。

```text

seal_groom_v7.py
finish_portrait_v7.py
export_portrait_v7.py
npm.cmd run assets:portrait
```
